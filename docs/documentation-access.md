# Documentation Access and Serving

## Current Status

The project has **two types of documentation**:

1. **API Documentation (Interactive Web Interface)**: Automatically generated by Django Ninja
   - **Location**: `http://localhost:8000/api/docs` (when Django server is running)
   - **Format**: Interactive Swagger/OpenAPI interface
   - **Access**: Available immediately when the Django development server is running

2. **Project Documentation (Markdown Files)**: Stored in the `docs/` directory
   - **Format**: Markdown files
   - **Access**: View in IDE, GitHub, or set up a local server

## How to Access Documentation

### Option 1: API Documentation (Interactive Web Interface) ⭐ **RECOMMENDED FOR API**

**Django Ninja automatically generates an interactive API documentation interface.**

**Steps:**
1. Start the Django development server:
   ```bash
   cd fkapi
   python manage.py runserver
   ```

2. Open your browser and navigate to:
   ```
   http://localhost:8000/api/docs
   ```

**Features:**
- ✅ Interactive Swagger UI interface
- ✅ Test endpoints directly from the browser
- ✅ See request/response schemas
- ✅ View authentication requirements
- ✅ Try out API calls with real data
- ✅ Download OpenAPI schema (`/api/openapi.json`)

**What you'll see:**
- All API endpoints organized by tags (System, Clubs, Kits, Seasons, etc.)
- Request parameters with descriptions
- Response schemas with examples
- Authentication information (if enabled)
- Rate limiting information
- Error response formats

**Production Access:**
- In production, the docs are available at: `https://your-domain.com/api/docs`
- Consider protecting it with authentication if it's sensitive:
  ```python
  from django.contrib.admin.views.decorators import staff_member_required
  api = NinjaAPI(docs_decorator=staff_member_required)
  ```

### Option 3: GitHub Web Interface

When the repository is pushed to GitHub :
- Documentation is automatically rendered as HTML
- Navigate to `docs/` folder in the web interface
- Click on any `.md` file to view formatted documentation
- Links between documents work automatically

**Example URLs:**
- GitHub: `https://github.com/your-org/FKApi/tree/main/docs`


### Option 4: Local Markdown Server (For Project Documentation)

You can serve the documentation locally using a simple HTTP server:

**Using Python:**
```bash
# Python 3
cd docs
python -m http.server 8001

# Access at: http://localhost:8001
# Note: Markdown files will show as plain text, not rendered HTML
```

**Using Node.js (with markdown rendering):**
```bash
# Install markdown-server globally
npm install -g markdown-serve

# Serve docs directory
cd docs
markdown-serve

# Access at: http://localhost:8080
```

**Using MkDocs (Recommended for Better Experience):**
```bash
# Install MkDocs
pip install mkdocs mkdocs-material

# Initialize (if not already done)
mkdocs new .

# Edit mkdocs.yml to configure
# Serve locally
mkdocs serve

# Access at: http://localhost:8000
```

## Recommended: Setting Up MkDocs

MkDocs is a fast, simple, and beautiful static site generator for documentation.

### Quick Setup

1. **Install MkDocs:**
```bash
pip install mkdocs mkdocs-material
```

2. **Create `mkdocs.yml` in project root:**
```yaml
site_name: FKApi Documentation
site_description: Football Kit Archive API Documentation
site_url: https://your-domain.com/docs

theme:
  name: material
  palette:
    - scheme: default
      primary: blue
      toggle:
        icon: material/brightness-7
        name: Switch to dark mode
    - scheme: dark
      primary: blue
      toggle:
        icon: material/brightness-4
        name: Switch to light mode

nav:
  - Home: README.md
  - Getting Started: getting-started.md
  - Celery Setup: celery-setup.md
  - Architecture: architecture.md
  - Data Flow: data-flow.md
  - API:
    - Endpoint Catalog: api/endpoint-catalog.md
    - Usage Examples: api/usage-examples.md
  - Developer Onboarding: developer-onboarding.md
  - Troubleshooting: troubleshooting.md

markdown_extensions:
  - pymdownx.highlight
  - pymdownx.superfences
  - pymdownx.tabbed
  - admonition
  - pymdownx.details
```

3. **Serve locally:**
```bash
mkdocs serve
# Access at: http://localhost:8000
```

4. **Build static site:**
```bash
mkdocs build
# Output in: site/
```

5. **Deploy to GitHub Pages:**
```bash
mkdocs gh-deploy
# Automatically deploys to: https://your-username.github.io/FKApi/
```

## Alternative: Read the Docs

Read the Docs is a free documentation hosting service.

### Setup Steps

1. **Create `readthedocs.yml` in project root:**
```yaml
version: 2

build:
  image: latest

python:
  version: 3.11
  install:
    - method: pip
      path: .
      extra_requirements:
        - docs

sphinx:
  configuration: docs/conf.py
```

2. **Connect repository to Read the Docs:**
   - Go to https://readthedocs.org/
   - Import your GitHub repository
   - Configure build settings
   - Documentation will be available at: `https://your-project.readthedocs.io/`

## Best Practices

1. **Keep documentation in sync with code**
   - Update docs when adding features
   - Review docs during code reviews

2. **Use relative links**
   - Links work in both GitHub and local viewing
   - Example: `[Getting Started](getting-started.md)`

3. **Maintain the index**
   - Keep `docs/README.md` updated
   - Add new documents to the index

4. **Version control**
   - All documentation is versioned with the code
   - Use Git tags for documentation versions
